Sofia 架构全览

一个长期运行的个人陪伴 Agent：一个人格、一条永不结束的 Timeline，同时活在桌面 Live2D、Telegram 等多个 Channel 里。内核只负责 Queue、调度、渲染、Timeline、Agent Loop 和 Hook 分发，其余全部是 Extension。

内核Extension依赖 @earendil-works/pi-ai · pi-agent-core 1.5.x

本页是 docs/architecture.md 的图示摘要，细节以该文档为准。术语见 GLOSSARY.md，取舍见 docs/adr/。

唯一、永久、只追加的经历记录，所有 Room 共享。

一次连续的思考行动，同一时刻至多一个。

Run 中一次模型回复加其工具调用。

Run 所关注的 Room，回复默认发到这里，可以没有。

系统提示词里具名、少变的一段。

Run 开始时写入的“想起来的东西”，供检索式记忆扩展使用。

内核写入的旁白：Run 失败、中断、投递失败、被打断。

Compaction压缩

用摘要替换最旧的工作上下文，Timeline 本身不删。

Silence Token

整条回复等于 [[NO_REPLY]] 时表示不说话。

Trace

可选的行为观测记录，泳道图的数据源。

构件

唯一的插件单位。Channel、人设、记忆、压缩都是扩展。

Model Role模型角色

→

→
同 Room 正在 Run？是：agent.steer()，Turn 结束后注入，不防抖
否：进该 Room 的桶
→
防抖安静 debounceMs（1500）或从首条起满 maxWaitMs（5000）→ 就绪
→
调度空闲时选优先级最高、同级最早的桶，一次取走全部 Signal 开 Run
  • 优先级由 Channel 标：主人私聊 high，群聊 normal，内部 Signal low。
  • 不抢占：群聊 Run 进行中来了私聊，等它结束后立刻处理。
  • Run 结束时还没注入的 steer：peekQueuedMessages() 取副本再清空，Signal 放回原桶，notice 直接写入 Timeline。
  • 每条消息都会唤醒她，回不回由模型决定。

Run 生命周期 §5

  1. 记录 runs 表；如有需要或有待压缩标记，先压缩压缩期间调度器等待，视同占用唯一思考流
  2. 从 Timeline 重建 agent.state.messages每个 Run 都重建；state.messages 只是工作副本
  3. 设置工具注册表、调用 Section provider，比较差异工具差异由 loop 自动声明 toolsAdded / toolsRemoved；Section 变化才出补丁
  4. run_start hook 收集 recall
  5. agent.prompt([section 补丁?, recall?, …signals])Run 进行中所有消息只经 message_end 落盘
  6. Turn：流式回复 → 自动投递 → 工具执行 → turn_end → 注入 steer → 必要时 Turn 间压缩Turn 上限 maxTurnsPerRun 默认不限制
  7. agent_end → 更新 runs 状态 → run_end → 处理残留 → 调度下一个

自动投递 ADR-0004

  • 每条 assistant 消息结束时投递其文本，thinking 不投递。
  • 整条去掉首尾空白和方括号、忽略大小写后等于 NO_REPLY 就不发。
  • 没有 Focus Room 不投递。显式 {扩展名}_send 工具并存，不去重。
  • 不 await；同 Room 串成一条发送链保序。
  • 流式时，已有文本可能还是 Silence Token 开头就先扣住。

出错与中止

  • 流式重试只在第一个内容事件之前，默认 3 次。
  • Run 失败：写 notice，调用 onRunError 告诉 Room，Signal 不重放。
  • 只把“她以为成功、实际失败”的事告诉她：投递持续失败时，Run 中 steer 注入 notice，已结束就写入 Timeline，不唤醒新 Run。
  • sofia.abortRun()：desktop 停止按钮、Telegram /stop、admin。写 notice「主人打断了你」。
  • hook 超时：默认 10s，压缩相关 120s。

一次模型请求的上下文 §6 §7

system：kernel · persona · memory · channel:telegram · channel:desktop …Section，少变，保 prompt cache
tools：telegram_send · desktop_expression · desktop_motion …Run 开始时生效，不随 Room 变
user：<summary> 交接简报最近一次压缩的摘要
最近约 20k token 原文（signal / assistant / toolResult / notice）切点落在 Run 边界
user：<recall>… + 本次 Signal（合并为一条）每个 Run 都变，放 user 消息
  • 规则：很少变的放 Section，每个 Run 都变的放 user 消息。
  • 系统提示词也存在 Timeline 里：首条全量，之后只追加差异补丁（pi-ai 1.5 的 SystemMessage sections）。
  • 工具名由内核自动加 {扩展名}_ 前缀，扩展只写动作名，天然不重名。
  • error / aborted 的 assistant 条目由 pi-ai 发送时跳过，内核只在估算 token 时排除。

压缩 §7.3

触发超过 窗口 − 16k；或溢出；或 sofia.compact() 主动触发
→

→

→

→
compacted内核 await，所有扩展收到；ext-memory-md 在此增量编辑 memory.md
→

  • 摘要失败（出错或超时）：和 pi 一样，这次不压缩、上下文不变，下次检查点再触发。
  • 一个压缩扩展都没启用时才兜底：丢弃切点前的内容。
  • 溢出恢复：isContextOverflow → 强制压缩 → 重建 → agent.continue()，只试一次。
  • memory Section 只在 rebuild 时刷新，两次压缩之间系统提示词字节不变（ADR-0006）。

需要返回值、或内核必须等它完成的做成 hook；只需知道“发生了什么”的只放事件流。hook 按 config 里扩展的顺序执行。

存储 §7.1 ADR-0003

timeline.db（内核独写，SQLite WAL）

  • entries：seq、id、at、type、run_id、room、data（JSON），只追加。
  • 条目类型：system · signal · recall · assistant · toolResult · notice · compaction。
  • runs：focus_room、开始结束时间、status（ok / error / aborted / interrupted）。
  • 扩展只能 timeline.query 只读。

启动恢复 §7.4

  • 从最近的 compaction 重建上下文，再比较 Section 和工具差异。
  • 未结束的 Run 标为 interrupted，写 notice「你刚才被中断了」，不重放。
  • Queue 只在内存，崩溃时排队中的 Signal 会丢失，这是接受的风险。

0001一个人格、一条 Timeline、同一时刻一个 Run；接受跨 Room 上下文泄露
0002基于 pi-ai + pi-agent-core 自写内核，只借鉴 pi-coding-agent 的 hook 形状

v1 明确不做 §14

  • 多 Agent、并行 Run、抢占
  • 跨 Channel 合并 Contact；ownerOnly 工具权限；私聊内容过滤；正文防伪造
  • 可插拔存储；Queue 持久化；单扩展热重载；自定义渲染器 hook
  • 向量或全文检索记忆；记忆更新失败后的补做
  • 图片存文件引用、旧图降级为文字
  • Timeline 分支
